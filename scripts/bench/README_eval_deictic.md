# eval_deictic.py — Week-4 Deictic Resolver Eval

LLM-as-judge harness for the Week-4 acceptance criterion:

> **≥80% of a 50-task deictic eval must resolve the correct referent.**

---

## Quick start

```bash
# The judge needs the Anthropic SDK — it's in the `dev` dependency group:
uv sync                       # installs anthropic (or: uv pip install anthropic)

# Run the 6-task sample (placeholder images)
uv run python scripts/bench/eval_deictic.py

# Run with relational-deixis full-frame escalation
uv run python scripts/bench/eval_deictic.py --escalate-full-frame

# Write per-task JSONL results
uv run python scripts/bench/eval_deictic.py --out results/week4_deictic.jsonl

# Smoke-test with a single task
uv run python scripts/bench/eval_deictic.py --limit 1
```

---

## API keys required

Two keys are needed. Set them in the environment or add them to `.env` in the repo root:

```
GEMINI_API_KEY=...       # Gemini Live (the model under test)
ANTHROPIC_API_KEY=...    # Claude judge
```

The script reads `.env` as a fallback if the env var is not set.

## IMPORTANT CAVEAT — utterances are TEXT-injected (bypasses ASR)

Utterances like `"Fix this"` are injected directly via
`send_realtime_input(text=utterance)`, **not** via synthesised or recorded speech.

**What this tests:** visual grounding — whether the model correctly resolves the deictic
reference (`"this"`, `"that"`, `"these"`) given the tile image + cursor position + window
context.

**What this does NOT test:** speech transcription (ASR). An error where the model
mishears `"Fix this"` as `"Fix disc"` would be invisible here. The ASR path is tested
separately with the `measure_ttfb.py` harness (which uses `say`+ffmpeg PCM).

This is intentional for Week 4: keep the visual-grounding eval free of ASR noise.

### How the model's words are read

`gemini-3.1-flash-live-preview` does **not** support TEXT-only output (the connection is
closed with `1007 ... response modalities (TEXT) is not supported`). The eval therefore
requests `["AUDIO"]` with `output_audio_transcription=True` and reads the streamed
transcript via `on_text_out`. It also runs under **automatic VAD** (no `activity_start`/
`activity_end`): text input alone triggers the model's turn, and the server rejects manual
VAD's `realtime_input_config` when combined with transcription. None of this changes what is
measured — only how the response text is captured.

## Scoring

The judge (Claude via the Anthropic API) rates each model response as:

| Verdict | Meaning | Counts as pass? |
|---|---|---|
| `correct` | Model identified the same referent as `expected_referent` | **YES** |
| `ambiguous` | Plausible but not clearly confirming the expected referent | **NO** |
| `incorrect` | Wrong element, refused, or ignored cursor/pointer context | **NO** |

**Only `correct` counts toward the 80% bar. `ambiguous` does NOT count as a pass.**

The judge prompt instructs Claude to be strict: vague hedging without naming a specific
element should be scored `ambiguous`, not `correct`.

## Full CLI reference

```
uv run python scripts/bench/eval_deictic.py [OPTIONS]

  --model MODEL             Gemini Live model (default: models/gemini-3.1-flash-live-preview)
  --tasks PATH              Path to deictic_tasks.jsonl (default: fixtures/deictic_tasks.jsonl)
  --escalate-full-frame     Send full frame at turn start (relational-deixis mode)
  --judge-model MODEL       Anthropic model for judge (default: claude-sonnet-4-5)
  --limit N                 Only run the first N tasks
  --out PATH                Write per-task JSONL results to this file
```

Exit codes: `0` = passed the 80% bar, `1` = setup error, `2` = did not pass.

---

## JSONL output format

Each line in the `--out` file is a JSON object:

```json
{
  "id": "task_001",
  "utterance": "Fix this",
  "model_response": "The function at the cursor appears to have a syntax error...",
  "judge_verdict": "correct",
  "judge_reason": "Model correctly identified the highlighted function under cursor",
  "passed": true
}
```

---

## Fixture format (`deictic_tasks.jsonl`)

One JSON object per line:

```json
{
  "id": "task_001",
  "image_path": "fixtures/images/task_001.jpg",
  "cursor_tile_x": 210,
  "cursor_tile_y": 228,
  "utterance": "Fix this",
  "expected_referent": "the highlighted Python function at the cursor",
  "expected_referent_keywords": ["function", "fix", "cursor", "code", "highlighted"],
  "tags": ["code", "single-referent", "imperative"],
  "notes": "..."
}
```

`image_path` is relative to `scripts/bench/`. `cursor_tile_x/y` are the cursor offsets in
logical points within the tile (used to build the `[context]` annotation).

## Replacing placeholder images with real screenshots

The 6 images under `fixtures/images/` are synthetic placeholders generated by ffmpeg
(solid-color backgrounds with geometric shapes). **They do not contain meaningful visual
content** — the model will receive a colored rectangle and must rely on the text annotation
alone. This means scores on these placeholders are NOT indicative of production performance.

To build a meaningful 50-task eval:

1. Capture real macOS screenshots with the pointer agent running:
   ```bash
   uv run pointer-agent --tiles --output .data/eval_captures.jsonl --limit 200
   ```
2. Extract tile images from the JSONL (`hover_region.tile_b64`, base64-decode to JPEG).
3. Label each task: write `utterance`, `expected_referent`, and `expected_referent_keywords`.
4. Aim for coverage: ~20 code tasks, ~15 browser/text, ~10 relational/multi-referent, ~5 image.
5. Add the 50 tasks to `fixtures/deictic_tasks.jsonl` (append after the 6 sample tasks or
   replace them).

For relational tasks (task_005-style), enable `--escalate-full-frame`. When set, the eval
sends an extra full-frame image on the video channel: it uses the task's optional
`full_frame_path` if present, otherwise falls back to `image_path`. (In production the full
frame is force-sent at `activity_start`; under the eval's automatic-VAD path that hook is
inert, so the eval sends it directly — the grounding signal to the model is identical.)
